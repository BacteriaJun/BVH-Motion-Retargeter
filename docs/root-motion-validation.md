# Root motion and FBX validation

The Unreal profiles generate a UE-friendly humanoid hierarchy. They do not reproduce Epic's complete Manny/Quinn deformation/control rig. Native Unreal Engine import has not been run by these tests.

## Horizontal travel uses world axes

`_split_pelvis_motion_to_root` samples the evaluated pelvis position in Blender world coordinates. It assigns world X/Y travel to the new root and retains vertical body motion in the pelvis. Pose translation channels use each bone's rest axes, so copying local channels 0 and 1 is insufficient: an imported bone's local Y commonly points along Blender world Z.

The implementation converts the requested root pose and the original pelvis pose back through the actual bone/rest/parent transforms. A nonidentity object rotation, constant uniform scale, and object-level rotation/translation animation are included in the native regression set. The sampled pelvis, head, hand, foot and index-base world positions remain unchanged within numerical tolerance.

Newly generated root bones start at the armature/model origin `(0, 0, 0)`. An existing root keeps its authored rest head and tail. The allocation fixes world height to the first sampled root head height; with a transformed armature this need not be world Z=0. This is an explicit model-origin convention, not an estimate of the physical ground. Verify the root and target character retarget configuration together.

## Scope and refusal conditions

This is an integer-frame FK bake. It preserves sampled transforms; it does not guarantee the original unsampled Bezier interpolation. Export samples every frame with simplification disabled.

An already split root, existing root keyframes, constraints, active NLA/drivers, multiple Action layers, nonidentity unkeyed root pose, or nonuniform/animated object scale require baking or returning to the original Action. The function computes the allocation before committing a separate Action; it does not silently add a second copy of root movement.

The FBX preflight checks finite animation/pose data and large root discontinuities in the chosen export range. A motion discontinuity is a diagnostic rather than proof of capture error. Explicitly allowing discontinuities does not authorize NaN/Infinity. Terminal invalid packets should be reviewed or excluded from the export range; they cannot be repaired with a two-sided short-gap interpolator.

## Native test entry points

Run from the repository root, with an output directory outside the source tree:

```sh
blender --background --factory-startup --disable-autoexec --python-exit-code 1 \
  --python tests/blender/test_cleanup.py -- --output /absolute/new/cleanup-results
blender --background --factory-startup --disable-autoexec --python-exit-code 1 \
  --python tests/blender/test_fbx_profiles.py -- --output /absolute/new/fbx-results
```

The fixtures are original synthetic motion, generated by `tests/make_motion_fixture.py`. No customer captures or vendor character files are used.

`test_cleanup.py` checks original Action/pose/file preservation, finger and root-location channels, a synthetic rotation truth/error budget, Euler angles across a full-turn neighborhood, zero-strength Bezier preservation, scoped short root-gap repair, invalid tails/object motion/scale, and nonfinite nonroot data.

`test_fbx_profiles.py` checks Mixamo/UE4/UE5 export and native FBX reimport, names/hierarchy/sample counts/marker trajectories, world-axis root allocation, transformed and animated objects, existing-output protection, source frame/subframe restoration, duplicate root allocation, and incompatible profile refusal. It also round-trips the root-allocated variants through FBX.

Generated-fixture error reductions and successful representation round trips are not real-capture quality measurements.
